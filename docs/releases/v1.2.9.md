# Offline BMS 1.2.9 — Automatic reconnect

When a monitored battery goes out of Bluetooth range, Offline BMS now waits for that battery and resumes live readings when it returns. Previously the service stopped and the dashboard kept only the saved reading.

- Automatic reconnect is enabled by default in **Tools → Monitoring & recording**.
- Keep **Continue monitoring with the screen off** enabled for background reconnection.
- The dashboard and battery list show a waiting state, and cached readings remain labelled Saved until fresh telemetry arrives.
- Bluetooth off/on resumes waiting. Opening the app resumes the last requested battery using its saved encrypted credentials when required.
- Stop monitoring cancels pending reconnects and disables resume until you connect again. Switching batteries cancels the old attempt.
- Android waits for device availability instead of repeated scan windows; the BMS CPU wake lock is released while waiting. Android power management can still end the app process.
- Connection gaps use separate energy/session intervals. Reconnection never retries settings or balancing writes. Unsupported devices, rejected authentication and invalid layouts still need correction.

Install this APK over the existing app to retain profiles, keys and recorded history. Android 12 or later. Package and signing certificate are retained. Hardware return-to-range behaviour still needs confirmation on the user's phone and BMS; automated checks simulate the Bluetooth transport.

Validation: 655 automated checks/cases passed (519 protocol/control, 40 storage, 96 Android runtime cases on API 31/35), plus APK signature/archive/alignment checks and visual review of dark/light waiting screens.
